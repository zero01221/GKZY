## 一、本轮需求与拍板口径（复述）

用户本轮 4 项反馈，经提问拍板后口径如下（**严格遵守，不得自行扩大或缩水**）：

1. **「这个不要」= 删除整个「一分一段/代码」页面**（含顶部黄色数据版本横幅 `#q-banner`）及其导航入口。不是只删横幅、不是只删提示文字。
2. **「智能推荐不要」= 删除「智能推荐」页面及其导航入口**。仅删前端入口与页面，**不动推荐算法源码**（`server/recommend.mjs`、`/api/recommend` 保留）。
3. **一分一档表 = 用本地库数据渲染表格**，不再是外链。用户原话「根据链接提取信息在页面上展示」；实测夸克链接为 JS 空壳抓不到数据，拍板改用本地库 `score_range` 河北数据渲染，可筛年份/科类、按分数查位次。主展示必须是本地表格；夸克链接不作为主入口。
4. **省控线 = 补全物理类 + 修复表头与数据错位**。历史类保持现状；物理类按截图补全；表头与数据列一一对应、视觉对齐。
5. **院校查询 = 重做为多级交互**：学校列表（可搜索）→ 点进学校 → 选地区/年份/专业 → 显示各专业最低分、位次、计划数。原话要「录取人数和计划」，但库里**无录取人数字段**，拍板「先把 UI 完善，数据缺失的不写」——录取人数不显示/标暂无，不编造。

## 三、逐项变更规格

### C1 · 删除「智能推荐」页面与入口

**现状 → 目标**：侧边栏「志愿填报 / 智能推荐」（`data-tab="recommend"`）与 `<section id="panel-recommend">` 一并删除；用户进入系统后不再看到智能推荐入口。

- **用户故事**：作为本人，我不使用智能推荐，希望它从菜单消失，减少干扰。
- **交付范围**：
  - 删除 `index.html` 侧边栏 `<button data-tab="recommend">` 入口。
  - 删除 `index.html` 中 `<section id="panel-recommend">` 整段。
  - **保留** `server/recommend.mjs` 源码、`/api/recommend` 接口及所有推荐算法逻辑（不改、不删）。
- **验收标准**：
  1. 侧边栏与页面中检索不到「智能推荐」字样与 `data-tab="recommend"`。
  2. `git diff` 中 `server/recommend.mjs` 无改动；`/api/recommend` 仍可被程序调用并返回原结构。
  3. 其余导航项与功能不受影响。

### C2 · 删除「一分一段/代码」页面与入口（含顶部黄色横幅）

**现状 → 目标**：侧边栏「信息查询 / 一分一段/代码」（`data-tab="resource"`）与 `<section id="panel-resource">`（含「一分一段表」与「院校/专业代码」两个子页）整页删除；主内容区顶部黄色数据版本横幅 `#q-banner` 一并移除。

- **用户故事**：作为本人，我不需要「一分一段/代码」页和顶部那条黄色数据版本提示，希望整块移除，而不是只去掉提示文字。
- **交付范围**：
  - 删除 `index.html` 侧边栏 `data-tab="resource"` 入口。
  - 删除 `<section id="panel-resource">` 整段（含 `#res-rank`、`#res-code`、`#res-hint` 等全部子节点）。
  - 删除主内容区顶部 `#q-banner` 容器（`.q-banner`）。注意：该横幅当前是**全局元素**（位于所有 panel 之外，由 `quality-ui.js` 填充），删除后所有页面均不再显示；`quality-ui.js` 已有 `if(!banner) return` 守卫，无需改质量逻辑（见第六节不改边界）。
  - `web/plan-ui.js` 中仅服务于该页的函数（`initResource` / `refreshRankOptions` / `queryRankScore` / `showRankTable` / `queryCodes`）及其在初始化中的调用需清理或加空值守卫，避免引用已删除的 DOM（`#rk-*` / `#cd-*` / `#res-hint`）报错。
  - `web/lines-ui.js` 顶部外链常量 `YI_FEN_YI_DANG_URL` 与 `init()` 中对 `#nav-onepoint` 的绑定需移除（该外链入口由 C3 的本地页替代）。
- **验收标准**：
  1. DOM 中检索不到 `panel-resource`、`data-tab="resource"`、`#rk-*`、`#cd-*`、`#q-banner`。
  2. 打开任意页面，主内容区顶部不再出现黄色「数据版本…」横幅。
  3. 浏览器控制台无因引用被删 DOM 而抛出的 JS 错误（逐个点击剩余导航项验证）。
  4. 数据管理页的质量面板仍可正常渲染（横幅删除未破坏 `quality-ui.js`）。

### C3 · 新增「一分一档表」页（本地库表格）

**现状 → 目标**：原侧边栏「河北省一分一档表」是指向夸克外链的 `<a id="nav-onepoint">`；改为一个真正的应用内页面，数据取自本地库 `score_range`（河北），页面内可筛年份/科类、按分数查位次、查看完整分段表。**不再跳转外链。**

- **用户故事**：
  - US-C3a：作为河北考生，我想在页面内直接看到一分一档表，而不是点开一个抓不到数据的外链。
  - US-C3b：作为考生，我想选年份和科类后输入分数，立刻查到对应位次（累计人数）。
  - US-C3c：作为考生，我想看完整的「分数 / 本段人数 / 累计人数」表格，逐档核对。

- **页面字段与交互**：
  | 区域 | 控件 | 说明 |
  | --- | --- | --- |
  | 筛选 | 年份 select | 从本地库可用年份生成（河北约 2020–2026），倒序；默认最新有数据年份 |
  | 筛选 | 科类 select | 物理类 / 历史类，选项由该年份实际可用的科类决定（见风险 R2） |
  | 查位次 | 分数 input + 「查位次」按钮 | 输入分数，展示该分数对应的**累计人数（位次）** |
  | 表格 | 「查看完整表格」按钮 | 以表格列出该年份+科类全部分数段，列：**分数 / 本段人数 / 累计人数（位次）**，按分数降序 |

- **数据契约（架构师定具体实现，满足以下即可）**：
  - 数据来自本地库 `score_range(p,y,c,score,seg,cum)`，河北（标准省码 13，库内原始 `p` 值由 `gcdb.mjs` 映射）。
  - 可复用现有 `GET /api/resource/rank`（传 `year`+`type`，返回 `rows = [[分数, 累计人数, 本段人数], …]`、`total`、`range`、`gaps`、`full`），或新增专用端点（如 `/api/score-range`）——**由架构师二选一**。
  - 查位次走同一表的分数→累计映射；命中区间边界按现有 `realScoreToRank` 语义处理，前端如实标注是否为精确值。
  - 不依赖任何外部链接；缺失年份/科类显示「暂无数据」，不插值、不编造。

- **验收标准**：
  1. 打开新「一分一档表」页，页面内呈现表格，**不发生外链跳转**；DOM 中不再有夸克链接。
  2. 选择「河北 / 2026 / 物理类」，查看完整表格，能看到 `分数=140` 一行，其 `本段人数=13`、`累计人数=350991`（与主理人探明的样本一致）。
  3. 输入分数 140 点「查位次」，展示累计位次 350991。
  4. 切换年份（如 2025）与科类，表格数据随之变化；选到无数据的年份/科类（如 2026+历史类）显示「暂无数据」而非报错。
  5. 表头（分数/本段人数/累计人数）与数据列逐列对齐。

### C4 · 省控线补全物理类 + 表头数据对齐

**现状问题**：静态真源 `server/province-lines.mjs` 仅历史类 5 年齐全，物理类只有 2026/2025 本科；`lines-ui.js` 表格表头与数据列视觉对不齐。

**目标数据（唯一真源，缺失单元格不再存在；全部填满，无「暂无数据」）**：

| 年份 | 历史类·本科批 | 历史类·专科批 | 物理类·本科批 | 物理类·专科批 |
| --- | --- | --- | --- | --- |
| 2026 | 485 | 200 | 443 | 200 |
| 2025 | 477 | 200 | 459 | 200 |
| 2024 | 449 | 200 | 448 | 200 |
| 2023 | 430 | 200 | 439 | 200 |
| 2022 | 443 | 200 | 430 | 200 |

> 物理类本科批：2022=430 / 2023=439 / 2024=448 / 2025=459 / 2026=443；物理类专科批五年均 200；历史类保持现状。

- **用户故事**：作为考生，我想在同一张表里对照历史类和物理类的省控线，且表头和数据一一对齐，方便逐列阅读。
- **交付范围**：
  - `server/province-lines.mjs`：按上表补全 5 年 × 2 科类 × 2 批次 = 20 个单元格（保持「唯一真源」定位，`gcsource.batchLines()` hook 不变）。
  - `web/lines-ui.js`：修复表头与数据错位。二选一（由架构师定，必须视觉对齐）：
    - **方案 A（推荐）**：改为四列 `年份 | 科类 | 本科批 | 专科批`，每个年份展开历史/物理两行（共 10 行），每列都有值——让用户一眼看到补全的物理类，无需切换科类下拉。
    - **方案 B**：保留三列 `年份 | 本科批 | 专科批`，科类仍以下拉筛选，但确保表头数 == 数据单元格数、逐列严格对齐。
- **验收标准**：
  1. `GET /api/lines?provinceId=13` 返回 5 年数据，历史类、物理类本科/专科数值与上图逐格一致。
  2. 省控线页面：历史类 5 年数值与现状一致；物理类 5 年本科/专科全部有值，不再出现「暂无数据」。
  3. 表头列数 == 每行数据单元格数，视觉对齐（可截图核对，无错位/串行）。
  4. `batchLines()` 返回结构仍为 `{ "科类|批次": number }`，`plan.mjs`/`recommend.mjs` 取值方式不变（不改算法）。

### C5 · 院校查询重做为三级交互

**现状 → 目标**：原 `panel-score` 是「省份/科类/年份/院校/专业」一次性筛选的分数线查询；改为**三级下钻**：学校列表（可搜索）→ 点进学校 → 选地区/年份/专业 → 各专业最低分/位次/计划数表。

```mermaid
flowchart LR
    A[院校查询入口] --> B[一级: 学校列表<br/>搜索学校名称]
    B -->|点击某校| C[二级: 学校详情<br/>筛选 地区/年份/专业]
    C --> D[三级: 结果表<br/>专业/最低分/位次/计划数]
    D -->|返回| B
```

- **用户故事**：
  - US-C5a：作为考生，我想先看到有招生记录的学校列表，并能按名称搜索，快速找到目标学校。
  - US-C5b：作为考生，我想点进一所学校后，按地区/年份/专业筛选，只看我关心的录取数据。
  - US-C5c：作为考生，我想看到每个专业的最低录取分、位次和计划数，用来判断能否录取。

#### 一级：学校列表

| 项 | 规格 |
| --- | --- |
| 默认视图 | 点击「院校查询」即显示学校列表（不再显示旧的多条件筛选表单） |
| 搜索 | 学校名称关键词输入（模糊匹配，输入即筛/回车筛） |
| 列表数据来源 | **基于有 `major_adm` 记录的学校**（河北），而非 `school` 全表 5354 所；`major_adm` 的 `sid` 关联 `school(id,name,nature,lv)` 取名 |
| 列表列 | 学校名称；可附办学性质/层次（`nature`/`lv`，有值才显示）——**不显示「所在地区」**（`school.province` 多为空，见风险 R3） |
| 规模处理 | 学校数量可能数百，需分页或「加载更多」；具体方式由架构师定 |
| 交互 | 点击某校 → 进入二级；面包屑显示当前层级 |

#### 二级：学校详情 + 筛选

| 项 | 规格 |
| --- | --- |
| 头部 | 显示学校名称 + 返回列表按钮 |
| 地区筛选 | 下拉；本期按**生源地省份**语义实现，当前库=河北，默认河北（见风险 R3，需主理人最终确认维度） |
| 年份筛选 | 从该校有 `major_adm` 的年份生成（已知 2025 全量、2026 部分），默认取数据最全年份（建议 2025） |
| 专业筛选 | 专业名称关键词/下拉，取自该校在该年份的 `major_adm` 专业（`dict(t='major').v`） |
| 科类筛选 | 数据含物理/历史（`c`），建议作为可选筛选一并展示（用户未明确列出，但数据具备，默认「全部」） |

#### 三级：结果表（每专业一行）

| 列 | 数据来源 | 缺失处理 |
| --- | --- | --- |
| 专业名称 | `major_adm.mid` → `dict(t='major').v` | 无字典名则显示原始值/「—」 |
| 最低分 | `major_adm.min` | — |
| 位次 | `major_adm.rnk` | 2025 全带位次；无值显示「—」 |
| 计划数 | `plan_info.cnt`（经 `plan_code` 关联 `sid`+`mid`） | 无计划数据显示「—」；**明确是「计划数」，不得标成录取人数** |
| ~~录取人数~~ | **无此字段，不显示该列、不编造数值** | 若参考图布局需要占位，显示「暂无」 |

- **数据事实依据**：`major_adm` 河北 2025 有 48641 条且全部带 `rnk`；2026 约 4000 条（物理 3085/历史 915）；`plan_info.cnt` 与河北 2025 `plan_code` 覆盖率 100%。
- **数据契约（架构师定端点）**：学校列表、该校可用筛选项、专业录取行（含 `plan_info.cnt`）各需一个读取接口；**只读**，不改任何原始数据。可基于现有 `/schools`、`/score/special`、`gcdb.provinceMajor`/`schoolMajorAdmission` 组合或新增专用端点，由架构师定。
- **验收标准**：
  1. 进入「院校查询」默认显示学校列表，可按名称搜索（如输入关键字后列表收窄到匹配学校）。
  2. 列表仅来自有 `major_adm` 记录的学校；不出现只有 `school` 记录、无录取数据的学校。
  3. 点击学校进入详情，地区/年份/专业（及科类）筛选可用，切换后结果表随之更新。
  4. 结果表显示 专业名称 / 最低分 / 位次 / 计划数 四列，逐列对齐；数据与该校该年份 `major_adm` 一致。
  5. 结果表**不出现「录取人数」列或数值**（缺失数据不编造）。
  6. 可返回学校列表；浏览器控制台无因改版产生的 JS 错误。
