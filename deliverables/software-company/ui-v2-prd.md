## 一、原始需求复述

参考桌面原型 `C:/Users/Administrator/Desktop/index.html` 美化界面（蓝色渐变顶栏 + 左侧分组侧边栏 + 卡片式主内容 + 表格/标签），**功能仍用原系统真实功能**（原型中的假数据一律不要）。左侧导航重组为三组：「志愿填报」「信息查询」「我的方案」。删除个人自用不需要的对外话术（免责声明、数据来源标注、AI 张雪峰技能提示词），保留「怎么操作」的功能性说明。新增省控线页面（照截图录入河北 2022–2026 年数据）、一分一档外链、登录（admin/123456）、服务端持久化的收藏/生成记录/草稿箱（草稿可导入生成的方案进行编辑，用于模拟志愿填报）。

## 二、产品定义

### 2.1 产品目标（正交）

| # | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | **界面更清晰美观**：把现有 8 个平铺 tab 重组为分组侧边栏，降低找功能的成本 | 三组导航覆盖全部原功能入口；从侧边栏任一功能 ≤2 次点击到达 |
| G2 | **个人数据可沉淀**：收藏、生成记录、草稿从浏览器本地升级到服务端，登录后跨会话可查 | 登录后刷新/重开浏览器，收藏、历史、草稿数据仍在 |
| G3 | **补齐决策信息**：提供河北历年省控线与一分一档入口，减少外部查数 | 省控线页可切换到 5 个年份 × 历史/物理两组，缺失数据明确标注「暂无数据」 |

### 2.2 使用场景定位

单人本地使用（本人一台机器/一个浏览器），不涉及多用户协作、权限分级、公网发布。因此：**登录用于隔离/解锁个人数据入口，而非高强度安全边界**；数据存储于项目 `data/` 下的本地 JSON 文件。

## 三、信息架构（新导航树）

### 3.1 侧边栏结构

```

├─ 品牌「高考志愿助手」+ 副标题
└─ 右侧：未登录「登录」按钮 / 已登录「admin ▾ | 退出」

左侧侧边栏（分组）
├─ 志愿填报
│   ├─ 志愿参考          → 原「志愿方案」(plan) 页面，仅供改名，算法与交互不变
│   └─ 智能推荐          → 原「智能推荐」(recommend) 页面，入口保留
├─ 信息查询
│   ├─ 河北省控线        → 新增页面（见 3.2）
│   ├─ 河北省一分一档表  → 外链跳转夸克链接（新标签页）

│   ├─ 大学环境          → 原「大学环境」(campus) 页面

├─ 我的方案
│   ├─ 收藏的院校专业    → 原「我的志愿」(wishlist)，升级为服务端持久化（见 3.4）

│   └─ 草稿箱            → 新增页面，登录后可见（见 3.5）
└─ 系统〔侧边栏底部独立分组〕
```

**数据管理落位说明**：不并入用户业务三组，作为侧边栏底部独立「系统」分组入口，避免打乱用户明确指定的三组结构；其内部数据版本、质量面板等能力**不做改动**，仅迁移入口位置。若主理人希望未登录也能查看，可改为常显，不影响本次其他工作。

### 3.2 河北省控线页（新增）

- 表格结构：行 = 年份（2026→2022 倒序），列 = 科类/批次；顶部提供年份与科类切换，默认「历史 / 全部年份」。
- 数据照截图录入（**唯一数据口径，不得编造缺口**）：

| 年份 | 历史类·本科批 | 历史类·专科批 | 物理类·本科批 | 物理类·专科批 |
| --- | --- | --- | --- | --- |
| 2026 | 485 | 200 | 443 | 暂无数据 |
| 2025 | 477 | 200 | 459 | 暂无数据 |
| 2024 | 449 | 200 | 暂无数据 | 暂无数据 |
| 2023 | 430 | 200 | 暂无数据 | 暂无数据 |
| 2022 | 443 | 200 | 暂无数据 | 暂无数据 |

- 数据来源：优先走现有 `server/gcdb.mjs` 的 `batchLines(pid, year)`；**因该接口目前 2022–2024 河北返回空对象，本次需补齐河北 5 个年份数据**（可在 API 层补数据或内置本地静态表，由架构师定），使页面能稳定展示上表。「暂无数据」必须由后端明确返回空标记或前端按约定降级展示，禁止用相邻年份插值填充。
- 页面只呈现分数与批次，不输出任何来源/免责话术（见第五节删减范围）。

### 3.3 院校查询页

- 沿用原 `score` 页面的真实数据与查询逻辑（含院校/专业代码等资料库能力入口），**不改数据源**。
- 展示样式参考截图3：以卡片包裹，分「录取分数线」「专业分数线」两个标签页/区块，表格列含年份、院校/专业、批次、最低分、最低位次、计划数等原系统已有字段。
- 原页面的「收藏（☆）」按钮保留，点击写入服务端收藏。

### 3.4 收藏的院校专业

- 原 `wishlist` 页面改标题为「收藏的院校专业」，入口置于「我的方案」组首位。
- 收藏数据由浏览器 `localStorage` 迁移为服务端本地 JSON 文件；未登录仍可临时收藏到本地，登录后自动合并上传（按院校代码 + 专业代码去重）。
- 删除/清空操作同步服务端。

### 3.5 草稿箱（新增）

- 功能：新建草稿、编辑草稿行（院校专业组、专业、是否服从调剂、梯度、备注）、保存、删除、列表查看。
- **从生成方案导入**：选择一条生成记录 → 将其方案行映射为草稿行 → 进入编辑态；导入生成副本，不修改原生成记录。
- 表单字段与样式参考原型的草稿表（序号 / 院校专业组 / 专业 / 服从调剂 / 梯度 / 操作）。
- 全部数据存服务端本地 JSON，仅登录后可见。

## 七、技术规范要点

### 7.1 保留原功能的边界（强约束）

| 不得改动 | 说明 |
| --- | --- |
| 推荐算法 / 方案生成算法 | `plan`、`recommend` 的计算逻辑、冲稳保分级、录取概率算法保持原样，本次只改页面标题、入口位置与展示样式 |
| 质量数学 / 数据质量面板 | 质量分数、版本校验等计算与 `quality-ui.js` 逻辑不改，仅迁移入口 |
| 数据库 / 原始数据文件 | `data/` 下院校、分数线、一分一段、资源库等既有数据文件不改结构、不改内容；本次仅**新增**历史/草稿/收藏的应用数据 JSON |
| 省控线以外的数据口径 | 除 3.2 明确补齐的河北历年省控线外，不新增、不猜测任何数据 |

### 7.2 服务端数据（新增）

- 位置：项目 `data/` 目录下，纯本地文件，不上传、不同步。
- 建议拆分：`history.json`（生成记录与填报历史）、`drafts.json`（草稿）、`wishlist.json`（收藏）；均为 JSON 数组，每条记录带 `id` 与 `createdAt/updatedAt`。
- 写入策略：小数据量下每次写全量文件即可；并发写入加锁由架构师按 Node 单进程特性判断。
- 生成记录快照至少包含：生成时间、分数、位次、选科、意向条件、方案行数组（院校、专业组、专业、批次、梯度、概率等原字段）。

### 7.3 UI Design Draft

- 顶栏：左侧品牌「高考志愿助手」+ 副标题，右侧登录/用户信息；`position: sticky`。
- 侧边栏：宽约 220px，白底、右侧 1px 边框，分组标题小字灰体（志愿填报 / 信息查询 / 我的方案 / 系统），条目 hover 与 active 态用浅蓝底 + 主色文字。
- 主内容区：卡片式（白底、圆角 12px、浅边框 + 极淡阴影），页头 H1 + 副标题；表格用于省控线、院校查询、收藏、历史、草稿；冲/稳/保用红/蓝/绿标签。
- 配色沿用原型：primary `#1f5fbf`、primary-dark `#123f80`、bg `#f4f6f9`、text `#1f2937`、border `#e5e7eb`。
